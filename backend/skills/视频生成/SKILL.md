# 视频生成

接到视频生成任务时，按**质量优先纪律**执行。核心原则：**能生成交付不算本事，出片好看、符合意图、不浪费用户的钱才算。**
每家引擎的"好听点"不一样——**先看用户配的是哪个引擎（或用户点名要哪家），按下方对应引擎的官方规则写提示词。**

## 铁律（违反任何一条 = 交付不合格）

1. **提示词必须专业**：绝不允许把用户的一句话原样塞给 video_gen。用户的话是意图，你的话是导演脚本——按当前引擎的官方规则扩写。
2. **先想后生成**：生成一条要花真金白银（几毛到几元）。动 `video_gen` 前先在回复里写出你打算用的完整提示词，确认无歧义再调用。
3. **一次成片优先**：不靠反复生成碰运气——每次调用前过一遍「质量清单」，不过关不出手。
4. **如实交付**：AI 视频可能有物理瑕疵（手指、文字、快动作）。交付时描述镜头内容，不夸大；失败/换引擎重试要说明原因。

## 零抽卡工作流（核心打法——目标是"一枪命中"，不是"多抽几次碰运气"）

省钱省的不是档位，是**抽卡次数**。按下面顺序走，多数视频可以第一次就命中：

1. **需求不清楚就先不动钱**：用户只说"给我生成个猫"这种模糊需求 → 先把你的理解（引擎+档位+时长+完整提示词）列出来给用户确认，**用户点头才花第一分钱**。需求描述已足够具体（主体/场景/动作/风格都有）→ 直接展示提示词并生成，不额外打断。
2. **构图/主体要求高 → 首帧锁定（最强手段）**：
   - `image_gen`（本地 ComfyUI，**免费**）先出图 → 用户满意 → `video_gen` 传 `first_frame` 参数
   - 或直接用**用户上传的图**做首帧
   - 原理：构图和主体用图定死，视频模型只负责"动起来"——命中率高一个量级
   - 首帧图选择：角色一致性、产品展示、场景还原类任务**务必**用首帧；纯氛围镜头（海浪、天空）可不用
3. **时长克制**：一个动作 5 秒讲完就 5 秒——时长越长抽卡方差越大
4. **失败别硬抽**：同一提示词连续失败 2 次 → 换打法（上首帧 / 换引擎 / 简化动作），并告知用户原因。不要无声地连抽第三次。

## 通用提示词公式（各家通用的底座）

```
[主体与动作] + [环境与场景] + [镜头语言] + [光影与色调] + [氛围与风格] + [画质约束]
```

**正例**（海边日出）：
> 清晨海边日出：太阳从海平线缓缓升起，金色阳光在海面拉出长长的波光，几只海鸥掠过镜头前景。镜头低角度缓慢上摇，浅景深，暖金色调，电影感光影，胶片质感，画面干净稳定。

**反例**（不合格）：
> 「生成一个海边的视频」——没有主体动作、没有镜头、没有光影，出片纯靠运气。

## 分引擎官方攻略（生成前必读对应小节）

### 🌊 MiniMax 海螺 H3（provider=minimax）

- **时间线结构**（官方手册核心方法）：把提示词写成"时间线规格"——**起始画面 → 动作变化 → 镜头运动 → 声音 → 结束状态**，按顺序写
- **方括号镜头指令**（官方语法，直接嵌在提示词里）：`[Pan left/right]`（摇）、`[Zoom in/out]`（推拉）、`[Truck left/right]`（横移）、`[Tilt up/down]`（俯仰）、`[Push in]`（推进）、`[Pull out]`（拉出）、`[Static]`（固定）、`[Tracking shot]`（追踪）等——能精确控制运镜，比自然语言稳
- **锁镜头**：不想要镜头运动时，在提示词末尾加 "static locked camera, no camera movement, no shot change"
- **多镜头**：用 `[Shot 1]` `[Shot 2]` 分段，且最后一个 `[Shot N]` 必须写到视频结束帧；不明确需要就别用多镜头
- **原生音频**：H3 自带立体声——提示词里可以写声音（"环境音：海浪声，海鸥鸣叫"）
- 档位：H3-Max 480P 最便宜（约 ¥0.4/5s）；H3 768P/2K 质量更高

### 🏔️ 通义万相 wan3.0（provider=wan）

- **官方公式**：主体（描述）+ 动作/行为 + 场景环境 + 运镜方式 + 景别/光影/氛围 + 音频描述
- **音频描述**：wan3.0 支持有声视频——提示词末尾写"环境音/音效"（音频开关在配置里，有声更贵）
- **美学词加分**：「复古文艺感」「晴天光」「电影感光影」「胶片质感」这类风格词官方明确推荐
- **档位即成本**（实测）：`resolution` 480P（约 1 分钟出片、几毛钱）→ 720P → 1080P（超分 SR:1080、142s、几元）。**默认 480P，用户要"最好效果"才上 1080P**
- 多镜头/角色一致性：@主角 公式（@A + 动作 + 台词 + 场景）——需要参考素材，文生视频场景少用

### 🎬 字节 Seedance（provider=seedance，即梦同款）

- **运镜听指挥**：自然语言运镜词有效——「推近」「拉远」「环绕」「追踪」「升降」
- **时间戳分镜**（2.5 特性）：可用整秒时间戳控制节奏（"0-3s：…；3-8s：…"），单次最长 30 秒
- **@引用素材**：多素材时用 @ 分配（"@A 走向 @B"）——API 多参考场景用
- 适合：长镜头叙事、运镜复杂的片子

### ⚡ 快手可灵 Kling（provider=kling）

- **官方公式**：主体 + 主体动作 + 场景 +（镜头语言 + 灯光 + 氛围）
- **运镜写法**：「镜头推进」「镜头左移」；不想要运镜就写「固定镜头」
- **负面提示词**：配置里可设 negative_prompt，列最易出现的瑕疵（"模糊、变形、水印、多余肢体"），上限 2500 字符
- 组合运镜：环绕+推进、升起+横摇这类组合词有效

### 🖥️ ComfyUI 本地（engine=comfyui）

- 按**模板工作流**出片（backend/comfyui_templates/ 目录）：ComfyUI 搭好工作流跑通一次 → 开发者模式 → Save (API Format) → 放进目录 → 正向提示词改成 `{{prompt}}`
- 用户想要什么工作流就建什么模板；好模板可以直接复用社区分享的 API 格式工作流
- 生成免费但吃显存（12GB 卡与文字大模型互斥）；速度取决于显卡与采样步数

## 引擎与成本速查（价格为官方标准价，以各控制台实时价为准）

|---|---|---|---|---|---|
| wan wan3.0-video 480P | ★★★★☆ | ~60s | **0.30 元/秒** | **1.50 元** | **默认首选** |
| wan wan3.0-video 720P | ★★★★☆ | 更慢 | 0.60 元/秒 | 3.00 元 | 清晰度要求高 |
| wan wan3.0-video 1080P | ★★★★★ | ~140s | 1.20 元/秒 | 6.00 元 | 用户要"最好效果" |
| minimax H3/H3-Max 各档 | ★★★★☆+ | 1-3min | 官方仅公布 2K=0.8 元/秒；480P/768P 以控制台为准 | 以控制台为准 | 原生音频/镜头指令 |

**成本红线**：动手前按「单价 × 时长 × 镜头数」算总账告诉用户并确认。例：60 秒漫剧 @wan 480P = 0.3×60 = 18 元。
**引擎切换**：用户点名（"用海螺生成"）→ video_gen 传 `engine` 参数；没点名 → 用配置默认。报错信息会列出当前可用的引擎。

## 质量清单（出手前逐条过）

- [ ] 主体与动作具体（有可执行的动作描述，不是静态名词）
- [ ] 有景别与运镜（按当前引擎的运镜写法：海螺用方括号指令，其他用自然语言）
- [ ] 有光影与色调（情绪有锚点）
- [ ] 提示词长度 60–200 字（太短没信息，太长稀释重点）
- [ ] 时长匹配内容（一个动作 5s；多镜头叙事拆多次调用）
- [ ] 无文字/招牌类要求（AI 生成文字必乱码；需要文字用后期）
- [ ] 人物手部特写慎用（已知短板）
- [ ] 成本已告知用户（首次调用前）

## 多镜头叙事（进阶）

超过 10 秒的内容不要一条提示词硬塞——**拆成多条 video_gen，每条一个镜头**，交付时按镜头顺序列 attachments，说明拼接顺序。每条提示词保持主体/色调/光线一致（写明「同一场景、同一色调」），避免拼接跳戏。海螺可用 `[Shot N]` 一条出多镜头（注意末镜头要写到结束帧）。

## 长视频 / AI 漫剧（video_join 拼接流水线）

**各家单次时长上限**（API 的硬限制，绕不开，但可以拼）：

| 引擎 | 单次上限 | 说明 |
|---|---|---|
| MiniMax 海螺 H3 | 15s | 可续写（regeneration 接 base_video） |
| 万相 wan3.0 | 30s | 一次就够一个完整小场景 |
| Seedance 2.5 | 30s | 支持时间戳分镜 |
| 可灵 Kling | 15s（部分档 10s） | — |

**长视频正确做法 = 分镜流水线**（比如 60 秒短片 = 8~12 个 5 秒镜头）：

1. **先写分镜表**：把用户的故事拆成 N 个镜头，每个镜头一行（画面内容 + 镜头语言 + 时长），**在回复里给用户过目确认后再花钱**——这是长视频省钱的第一关
2. **逐镜生成**：每镜一次 `video_gen`，**同一引擎同一档位**（参数一致拼接才顺滑）；命名规范 `shot_001.mp4`、`shot_002.mp4`…
3. **角色/场景一致性**（漫剧的关键）：
   - 每一镜都用**首帧锁定**：第一镜出图定角色形象，后续镜头的首帧图都从同一形象衍生（改姿态/改景别，不改发色服装）
   - 提示词里写死角色描述（"橘白相间的短毛猫，绿眼睛"每镜都带）
4. **合成**：`video_join` 按 `files: ["shot_001.mp4", ...]` 顺序拼接（自动重编码，不同源也能接）
5. **交付**：成片 + 分镜表对照说明

**AI 漫剧加强**（可选）：`speak` 生成旁白音轨 → 用 shell_exec + ffmpeg 把旁白混进成片；BGM 同理。字幕建议后期加（AI 直出文字会乱码）。

**成本提醒**：长视频总价 = 单价 × 总秒数，与镜头数无关（wan 480P：60 秒成片 = 0.3×60 = **18 元**；1080P = 72 元）——**动手前必须把总成本告诉用户并确认**。
