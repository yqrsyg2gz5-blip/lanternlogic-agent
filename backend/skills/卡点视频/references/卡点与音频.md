|---|---|---|

### 1.2 路线 A 的算法要点（读代码得来）

`beatmap.mjs` 只做调度，算法全在同目录 `audio-analysis.mjs`（142 行）：

| 函数 | 做法 |
|---|---|
| `decodePCM(file, sr=11025)` | ffmpeg 解码成 `f32le` 单声道 |
| `onsetEnvelope(x, sr, {fps:100, win:1024})` | 自己实现的**基-2 FFT**，对 log 幅度谱做**谱通量**（只累加正向差分）；同时输出全频带 `env` 与低频带 `low`（180 Hz 以下，用于找强拍） |
| `onsetPeaks(env, fps, {k:1.5, minGap:.08, span:.5})` | 移动阈值 + 局部极大的 onset 峰值 |
| `tempoOf(env, fps, a, b, {lo:80, hi:180})` | **自相关**求某段速度，抛物线插值细化 |
| `localTempo(env, fps, {win:8, step:4})` → `tempoCurve(tempo, fallback=120)` | 每 4 s 一个 8 s 窗口的局部速度，插值成 `t => bpm` |
| `trackBeats(env, fps, tempoAt, {tight:100})` | **Ellis 风格动态规划节拍跟踪**：每帧得分 = 自身 onset 强度 + 一个节拍周期前的最佳得分，偏离局部速度罚 `tight * log(p/P)^2`；从尾部最优回溯 |
| `loudness(x, sr, win=2)` | 每窗口 RMS dB |

主脚本 `beatmap.mjs` 的流程：解码 → `onsetEnvelope(win:512)` → `localTempo`→`tempoCurve`→`trackBeats` → **强拍判定**（对 `mod bpb` 的每个相位累加 `beats[i]` 附近的低频能量，取最大的那个——因为 kick 和贝斯落在「一」上）→ 每小节算 BPM 再中值滤波合并成常量速度段 → 算常量速度映射相对真实跟踪节拍的**最大漂移** `maxDriftMs`。

## 3. ★节拍复核（三条低成本手段，至少用两条 + 一条人工记录）

### 3.1 复核 A · 看倍速关系（30 秒，先做这条）

算 `检测值 / 真值`。**接近 1.5 / 2 / 0.5 就先怀疑倍频/半速**（含 ×2、÷2、×1.5、÷1.5 四种）。

### 3.2 复核 B · 拿检测出的网格去「踩点」叠听

用检测出的 `beats` 生成提示音轨，和原曲叠起来听：

```python
# tools/make_click_track.py —— ★★ 2026-10-12 修：旧版那条 ffmpeg 命令**只出一响** ✗
#   现场：`-f lavfi -i "sine=frequency=1500:duration=0.03"` 只是**贴在 t=0 的一个 0.03 秒音**，
#   不是"每隔一拍来一下" ⇒ 实测残差里只有 **1 响（−25.5 dBFS）** ⇒
#   判据"每一响都落在鼓点上"**根本无从执行** ✓（本项目小样实测踩到 ✓ 别再照抄 ✗）
#   正确做法：按 data/beats.json 的**每个时间点**逐条 adelay 摆 click ✓
import json, subprocess
FF = r"D:\MiniMax Design\current\resources\ffmpeg\ffmpeg.exe"
raw = json.load(open("data/beats.json", encoding="utf-8"))
beats = [b["t"] if isinstance(b, dict) else b for b in raw["beats"]]     # 秒
ins, fc, labels = ["-i", "music.wav"], [], []
for i, t in enumerate(beats):
    ins += ["-f", "lavfi", "-t", "0.03", "-i", "sine=frequency=1500"]
    ms = int(round(t * 1000))
    fc.append(f"[{i+1}:a]volume=0.6,adelay={ms}|{ms}[c{i}]")
    labels.append(f"[c{i}]")
fc.append("".join(labels) + f"amix=inputs={len(beats)}:normalize=0[clicks]")
fc.append("[0:a][clicks]amix=inputs=2:normalize=0[out]")
subprocess.run([FF, "-y", *ins, "-filter_complex", ";".join(fc),
                "-map", "[out]", "music_with_clicks.wav"], check=True)
```

**判据**：提示音**每一响都必须落在鼓点上**；有半拍错位或整段错位即判初稿错。
（★ 判据能成立的前提是**每拍一响** ✓ —— 旧命令只出一响，等于没做这条复核 ✓）

### 3.3 复核 C · 独立指标 `gridFit` 的圆集中度 R

`audio-analysis.mjs` 第 101–110 行（MIT，出处见文首）原样片段：

```js
// How firmly events (cuts) are locked to a beat grid. Each event gets a phase 0..1 inside its beat.
// R is the circular concentration of phases (1 = every cut at the same phase, random ≈ 1/sqrt(n)).
export function gridFit(events, beats) {
  if (beats.length < 2) return null;
  const ph = [];
  for (const t of events) { const i = beats.findIndex(b => b > t); if (i >= 1) ph.push((t - beats[i - 1]) / (beats[i] - beats[i - 1])); }
  if (!ph.length) return null;
  let c = 0, s = 0; for (const p of ph) { c += Math.cos(2 * Math.PI * p); s += Math.sin(2 * Math.PI * p); }
  const R = Math.hypot(c, s) / ph.length, phase = ((Math.atan2(s, c) / (2 * Math.PI)) + 1) % 1;
  const dist = p => { const d = Math.abs(p - phase) % 1; return Math.min(d, 1 - d); };
  return { R, phase, locked: ph.filter(p => dist(p) < .1).length / ph.length, n: ph.length, chanceR: 1 / Math.sqrt(ph.length) };
}
```

**判据**：把自己的切点时间（或 `beats` 自身）和 `beats` 喂进去，`R` **明显高于 `chanceR`** 才说明网格是对的。`chanceR = 1/sqrt(n)` 是随机基线。

### 3.5 参考项目的定量验收口径（video-shotcraft `music-beat-sync.md`，**读到**）

- **网格可信度**：对 beat 序列做最小二乘直线拟合 `t_i = t0 + i·T`，**残差 ≤ ±15 ms（半帧内）** 才说明「拍子是机器鼓点、网格可信」；残差大说明有变速段，需分段拟合。**勿信 `beat_track` 的 tempo 标量**——用整个序列拟合出 BPM。
- **实测基线**：一支 **70 s / 18 镜 / 131.97 BPM** 的电子鼓点宣传片，**渲后回测全部切点误差 ≤ 2.2f**（感知阈值约 3f）。
- **半速/双倍判据**：正确的网格下 **kick 应落在整数拍**；如果 kick 一半落半拍，多半是网格快了一倍。
- **复调/复杂鼓先分离 stem**：人声/弦乐会吃掉 beat 的击打音（`librosa.effects.hpss` 或 Demucs 分离 drums 后再测）。
- ⚠️ 以上「残差 ≤ ±15 ms」「≤2.2f」是**读到**的实测值，本机**未复现**。

### 4.2 排布规则（全部来自 motion-video-skill `build-timeline.mjs`，**读到**）

**规则 1 · 无锚点场景**：切在「上一句说完之后至少 **0.12 s** 的第一个拍上」。

```js
// 源自 build-timeline.mjs 第 32-33、42、79 行
const beat     = (n) => BEAT0 + BEAT * n;
const nextBeat = (t) => beat(Math.ceil((t - BEAT0) / BEAT - 1e-6));
const CUT_AFTER = 0.12;
const sceneAt = anchor.scene ?? nextBeat(prevVoiceEnd + CUT_AFTER);
if (sceneAt < prevVoEnd - 0.2) console.warn(`${id}: cut at ${sceneAt} clips the previous voice`);
```

**规则 2 · 有锚点 → 反向锚定**（把某一行放在想要的位置，倒推音频片段起点）：

```js
const lead  = (l.start - seg.a) / tempo;   // 片段起点到首词的距离（已被变速缩放）
const place = anchorLineAt - lead;         // anchorLineAt = 你希望首词出现的时刻（通常是 beat(k)）
```

锚点表实例（`build-timeline.mjs` 第 47–58 行）：

```js
const ANCHORS = {
  "s01-cover":  { scene: 0,        lines: [beat(3), beat(14)] },
  "s02-stats":  { scene: beat(20),  lines: [beat(22), beat(38)] }, // "Let's go!" 落在 drop 前的静默停顿里
  "s03-jev":    { scene: beat(40),  lines: [beat(40) + 0.12] },
```

**规则 3 · 行级切分（0.08 s 前导 / 0.15 s 尾巴，绝不越相邻中点）**：

> Each line is cut from the scene WAV between its aligned first/last word with 0.08 s pre-roll and 0.15 s tail, never past the midpoint to the neighbour line, then placed on the timeline independently.

```python
SEG_PRE, SEG_POST = 0.08, 0.15
for i, l in enumerate(lines):
    prev_mid = (lines[i-1]["e"] + l["s"]) / 2 if i else 0.0
    next_mid = (l["e"] + lines[i+1]["s"]) / 2 if i < len(lines)-1 else float("inf")
    a = max(0.0, l["s"] - SEG_PRE, prev_mid)     # 绝不越过与相邻行的中点
    b = min(l["e"] + SEG_POST, next_mid)
    # ffmpeg: atrim=start=a:end=b,asetpts=PTS-STARTPTS
```

**规则 4 · 变速必须同步缩放词时间戳**：clip 内时刻 `x` 映射到时间线一律 `place + (x - seg.a) / tempo`，**包括每个词的 `s/e`**（`TEMPO = 1.08` 时最容易忘）。

**规则 5 · 必须先扣 `acOffset`**：排布前把整条音频**前移** `acOffset`（= 首词 `s` − mp3 可听起点，本机实测 **70–95 ms**，见第 6.2 节第 3 条）。
即 `place = on − acOffset`。**不扣的话画面/字幕会比人声早 70–95 ms，第 8.7 条永远不过**——这正是 18 秒那条片子卡在返工上出不来的原因。

**冲突处理**：与上一行重叠时告警并强制后推 **0.05 s**。

### 4.3 必须读的自检告警（每一条都对应一个看得见/听得见的缺陷）

- `clips the previous voice` —— 切点切进了上一句
- `overlaps previous line, pushed later` —— 两行配音重叠
- `voice runs past its scene end` —— 配音超出场景尾
- `12 aligned words vs 13 script tokens` —— `say`/`en` 分词与实际朗读不一致，**去改文本或重生成该场景**

### 4.4 时间线验收

① 无上述任何告警；② 每个场景 `start < end` 且首尾相接；③ 所有词时间落在其行的 `[on, off]` 内；④ 打印出的场景起点**全部落在拍号上**（人工确认）。

## 5. 关键帧怎么绑到节拍 / 词上

### 5.1 逐拍脉冲 + 强拍放大（motion-video-skill `composition-contract.md` 第 66–70 行，**读到**）

> Loop `n` over beats until `outroBeat`; on kick beats pulse a background layer (orbs or halftone), on kick downbeats scale a `#pulse` wrapper by ~1%. **Keep it subtle: reactions are texture, cuts and drops carry the rhythm.**

```js
const B      = (n) => TIMING.beat0 + TIMING.beatLen * n;                 // 拍 -> 秒
const isKick = (n) => TIMING.kick.some(([a, b]) => n >= a && n < b);

for (let n = 0; n < outroBeat; n++) {
  if (!isKick(n)) continue;
  const t = B(n);
  gsap.fromTo('#orbs',  { scale: 1 }, { scale: 1.02, duration: 0.18, yoyo: true, repeat: 1 }, t);
  if (n % 4 === 0) gsap.fromTo('#pulse', { scale: 1 }, { scale: 1.01, duration: 0.22, yoyo: true, repeat: 1 }, t);
}
TIMING.drops.forEach((beatNo) => { flashAt(B(beatNo)); shakeAt(B(beatNo)); });
tl.set({}, {}, TIMING.duration);   // 让时间线长度 == 视频长度
```

### 5.2 词锚点查表 `W(sid, word, nth)`（等价实现）

```js
// 注意：TIMING 里的词是小写、去标点的，查询时要同样规范化
const norm = (t) => t.toLowerCase().replace(/[^\p{L}\p{N}'-]/gu, "");
function W(sid, word, nth = 1) {
  const w = (TIMING.scenes[sid]?.lines ?? []).flatMap(l => l.words).filter(x => x[0] === norm(word));
  if (w.length < nth) { console.warn(`W: "${word}" #${nth} not found in ${sid}`); return TIMING.scenes[sid].start; }
  return w[nth - 1][1];                       // 第 nth 次出现这个词的起始秒
}
```

**核心约定（照抄，因为它是让「改配音不用改画面」成立的原因）**：

> Choreograph with word anchors: "the chip appears on the word *OAuth*", not "0.8 s after the scene starts". Re-timing the voice then moves visuals with it.

### 5.3 逐帧函数路线（every-frame-is-code，不走 GSAP）

```js
function draw(t) {
  const beatNo = (t - TIMING.beat0) / TIMING.beatLen;
  const phase  = beatNo - Math.floor(beatNo);          // 0..1，拍内相位
  const pulse  = isKick(Math.floor(beatNo)) ? 1 + 0.02 * (1 - phase) : 1;
  // ...用 pulse 缩放要脉冲的层
}
```

**确定性要求**：拖尾/运动模糊**不要**用「半透明覆盖上一帧」（破坏确定性），改成在 `t - k*dt` 上重画若干次、透明度递减（运动模糊 **6–10** 个采样就够）。
**禁止项**：`Date`、`requestAnimationFrame`、CSS 动画/过渡；随机只用带种子的 PRNG（`mulberry32`）。

## 6. 配音（VO）：edge-tts 一条命令同时给音频 + 逐词时间轴

### 6.1 ★ 必须显式打开 `WordBoundary`

**本机实测**：`edge-tts` 默认**只发 `SentenceBoundary`，不发 `WordBoundary`**——默认参数下中英文 `WordBoundary` 计数都是 **0**。必须显式传 `boundary="WordBoundary"`。

实测（edge-tts 7.2.8，`D:\AI\agent-shell\backend\.venv` 里的解释器）：

```python
import asyncio, json, edge_tts

TEXT  = "LanternLogic Agent makes beat-synced videos. Every cut lands on the beat."
VOICE = "en-US-AriaNeural"

async def main():
    words, buf = [], bytearray()
    # 关键：boundary="WordBoundary"，否则一个词的时间戳都拿不到
    c = edge_tts.Communicate(TEXT, VOICE, boundary="WordBoundary")
    async for ch in c.stream():
        if ch["type"] == "audio":
            buf += ch["data"]
        elif ch["type"] == "WordBoundary":
            # offset / duration 的单位是 100 纳秒，除以 1e7 得秒
            words.append({"w": ch["text"],
                          "s": round(ch["offset"] / 1e7, 3),
                          "e": round((ch["offset"] + ch["duration"]) / 1e7, 3)})
    open("vo.mp3", "wb").write(bytes(buf))
    json.dump(words, open("vo.json", "w", encoding="utf-8"), ensure_ascii=False, indent=1)

asyncio.run(main())
```

### 6.2 三个必须写死的注意点

1. **末词之后有尾巴**。实测生成 11 个词的 mp3：最后一个词 `beat` 在 **5.35 s** 结束，而文件总长 **6.216 s**——**约 0.87 s 静音尾巴**。**切片段必须按最后一个词的 `e` 裁，不能按文件长度。**
2. **`edge-tts` 不在产品便携运行时（`runtime\`）里**（7.2.8 装在 `D:\AI\agent-shell\backend\.venv`；系统 Python 3.13 `import edge_tts` 失败 `ModuleNotFoundError`）。**这是用户已知缺口，本技能不修改任何环境**——要么装进产品运行时，要么在开发机用 agent-shell 的解释器调用。
3. **★ 词时间戳与「真正出声」之间有 70–95 ms 系统性滞后（必须补偿）**。`WordBoundary` 给的是边界时刻，mp3 解码后可听起点在其**之后**。本机实测（2026-10-12，18 秒真片的三条配音，`zh-CN-XiaoxiaoNeural`，24 kHz 10 ms 窗 RMS 取本行峰值 −35 dB 处为可听起点）：

   ```
   s01  首词 s=0.100  可听起点 0.190  滞后 90 ms
   s02  首词 s=0.100  可听起点 0.180  滞后 80 ms
   s03  首词 s=0.100  可听起点 0.170  滞后 70 ms     （制作方自己量到 95/80/75 ms）
   ```

   ⇒ **技能第 8.7 的「<50 ms」必须理解成「补偿后」**：每行量出 `acOffset = 首词 s − 可听起点`，
   写进 `vo-lines.json`，**排布时把音频整体前移**这个量，再进第 8.7 验收。
   **不补偿就永远不达标**，跟片子做得好坏无关。**报告里补偿前/后两个数都要写。**
   ⚠️ **未验证**：这个滞后是否跨音色/语速恒定——只测了单一音色的 3 行，**换音色必须重新量，不许照抄 0.08 s**。

### 6.6 卡拉OK字幕：两种做法（**两说并存**）

| 出处 | 做法 | 备注 |
|---|---|---|
| motion-video-skill | **英文有真实词级时间戳**；目标语言（越南语）**不做第二遍对齐**，按词数比例**借用**英文词的 onset | 见下方原样片段 |
| every-frame-is-code | **没有**卡拉OK逐词高亮机制；它有的是 `runtime/film.js` 的 `say()` **逐词弹出**（按节拍网格，默认每 0.5 拍一个词） | 与真实人声时间戳是**两套**东西 |

motion-video-skill 的借用实现（**读到**）：

```js
// Each VI word borrows the onset of the proportionally matching EN word
const toks = l.vi.split(/\s+/).filter(Boolean);
const en = l.words;
const words = toks.map((t, i) => ({ t, s: en[Math.min(en.length-1, Math.floor((i * en.length) / toks.length))][1] }));
// 保证 onset 单调递增，至少间隔 0.07 s
for (let i = 1; i < words.length; i++) if (words[i].s <= words[i-1].s) words[i].s = round(words[i-1].s + 0.07);
```

分块规则：`MAX_CHUNK = 9`（每块最多 9 个词）；遇标点 `[,.:;?!]` 且当前块 ≥3 词且剩余 ≥2 词且整行 >9 词时也切块。每块 `start = 首个词 onset − 0.12`，`end = min(下一块首词 onset − 0.16, 本行行尾 + 0.5)`。

> ⚠️ **对中文不建议照抄「按比例借用」**（中英词数比差异大）。edge-tts 的中文 WordBoundary **已实测可用**，直接用中文词时间戳更好。但「中文词 → 字幕 span 高亮」的渲染**本机未做（未验证）**。

### 7.2 小节拼接（bar-splice）的关键约束（**照抄，都是踩过的坑**）

`data/music-arrangement.json` 结构（原文）：

```json
{ "source": "./assets/audio/music/bgm-raw.mp3", "output": "./assets/audio/music/bgm.flac",
  "bpm": 110, "beat0": 0.04, "crossfade": 0.025, "fadeOut": { "beat": 244, "seconds": 6.5 },
  "segments": [ { "to": [0, 16], "from": 0, "role": "intro" },
                { "to": [40, 76], "from": 76, "role": "drop A" } ] }
```

- **整小节拷贝**（4 拍的倍数），保证乐句完整；目标 drop 要从「源曲里 build 刚好解决成 drop」的那一小节取

- AI 生成的音乐**不遵守每段的 `duration_ms`**（原文：*Expect the drops in the wrong places and fix that with the arrangement step, not by re-rolling.*）

| 来源 | 说明 | 本机状态 |

### 8.1 摆放：锚点模型（motion-video-skill `data/cues.json`，**读到**）

每条 cue 有 `sfx`、可选 `vol`（默认 **0.5**）、`offset`，以及**恰好一个**锚点：

| 锚点 | 含义 |
|---|---|
| `scene` + `word` (+ `nth`) | 该台词第 nth 次出现的 onset |
| `beat` | 音乐网格的第 n 个四分音符 |
| `abs` | 绝对秒 |
| `scene` + `at` | 场景切点之后 n 秒 |

**优先用 `word` / `beat` 锚点，因为它们能扛住重配时间。** 找不到词时脚本会 `throw new Error('cue: "word" #n not found in scene')`。
（参考：漫画版用了 19 个 SFX 文件、62 条 cue。）

### 8.2 听感规则（every-frame-is-code，**读到**）

- **静默之后不要有孤立的响亮一击**——*a hit in silence startles. The same hit inside a groove sounds fine.*
- **每个屏幕动作都要有声音**（出现=柔和 whoosh、撞击、点击、窸窣），音高音量用**种子**做微变化，否则重复会刺耳。
- 总线建议：所有声源进一个 `GainNode` → `DynamicsCompressorNode`（threshold **−18**、ratio **4**）→ 输出。"This glues the mix together and shaves off peaks."
- **长样本必须显式截断**：>5 s 的 SFX（某音效库里有 21 个）不给时长会拖到动作结束后还在响。

## 9. Ducking：说话时自动压低背景乐

### 9.1 ★ 路线 1（主推）：ffmpeg `sidechaincompress` —— **本机已实测可用**

```text
music  -5 dB  -> sidechaincompress(threshold=0.03, ratio=3, attack=15, release=350, makeup=1) keyed by the voice bus
voice  per-scene gain to -16 LUFS, peaks <= -1 dBFS
sfx    per-file gain to -16 LUFS, cue vol on top
sum -> 3.5 s fade out -> two-pass loudnorm I=-14 TP=-1.5 LRA=11 -> AAC 192k 48 kHz (./assets/audio/mix.m4a)
```

**目标**：**说话时音乐约低于人声 5 dB，空隙里回到接近人声电平。**

**参数来自血泪教训（原文）**：

> The first edition used −7 dB with ratio 5 / threshold 0.02: the music sat ~10 dB under the voice and viewers reported "there is no music". Measure with `build-timeline.mjs --stems` + `scripts/measure-mix-balance.py` instead of trusting the numbers by ear on laptop speakers.

**本机实测的 ducking 链路证据**：12 s 合成素材，空隙 **−26.07 / −26.94 dB** → 说话时 **−41.92 dB**（≈**15 dB** 压低）；人声 **−6.11 dB**。

取值函数同时受两个上限约束（原文）：

```js
const gainFor = (file, target) => {
  const { I, peak } = loudness(file);       // ffmpeg ebur128=peak=true 解析 Summary
  return Math.min(target - I, -1 - peak);   // 目标增益，但绝不把峰值推过 -1 dBFS
};
```

### 9.2 路线 2：手写增益自动化（every-frame-is-code，**读到**）

- **人声下的音乐低 10–15 dB**；ducking 用手写自动化：人声说话处把音乐增益压下去，**0.1 s attack、0.4 s release**
- 混音规则：静默之后不要有孤立的响亮一击；平台响度约 **−14 LUFS**（`ffmpeg -af loudnorm=I=-14:TP=-1.5:LRA=11`）

> ⚠️ **两条路线的推荐值不一样（5 dB vs 10–15 dB），这不矛盾**：路线 1 是「全片铺满的电子配乐 + 旁白」，路线 2 是「自制配乐 + 叙述」。**必须按自己的素材实测调整，不要照抄数字。**

### 9.3 ★ 必须测量，不要用耳朵在笔记本喇叭上判断

分别导出**被压过的音乐干声**和**人声干声**，按 `timeline.json` 里的台词 `[on, off]` 区间构造 speech 掩码，分别算三段 RMS dB。核心（源自 motion-video-skill `scripts/measure-mix-balance.py`，MIT，出处见文首）：

```python
import subprocess, json, numpy as np
SR = 8000
def dec(p):
    raw = subprocess.run(['ffmpeg','-v','error','-i',p,'-ac','1','-ar',str(SR),'-f','f32le','-'],
                         capture_output=True, check=True).stdout
    return np.frombuffer(raw, dtype=np.float32)
def db(x): return 10*np.log10(np.mean(x**2) + 1e-12)

timeline = json.load(open('data/timeline.json', encoding='utf-8'))
spans = [(l['on'], l['off']) for s in timeline['scenes'].values() for l in s['lines']]

m, v = dec('stem-music.wav'), dec('stem-voice.wav')
n = min(len(m), len(v)); m, v = m[:n], v[:n]
speech = np.zeros(n, bool)
for on, off in spans: speech[int(on*SR):int(off*SR)] = True

print(f"music under speech {db(m[speech]):.1f} dB | "
      f"music in gaps {db(m[~speech]):.1f} dB | voice {db(v[speech]):.1f} dB")
print(f"music sits {db(v[speech]) - db(m[speech]):.1f} dB under the voice")
# 目标：音乐在人声下约低 4–6 dB；~10 dB 会被听成"没有音乐"
```

**验收标准**：**音乐在人声下约低 4–6 dB**，且空隙里接近人声电平。（`~10 dB` 会被听成「根本没有音乐」。）
