## 2. 跑之前的两个准备（漏了必失败）

> ★★ **2026-12-13 新增：开工第一步先跑体检，别自己摸索**
>
> ```powershell
> & <python> tools\preflight.py
> ```
>
> 它一条命令查完 §2.1 / §2.2 / §2.3 三件事，**并把该设的环境变量打印成可直接复制的命令**。
> 真机上不走这一步的代价：agent 把步数全耗在试错上（实测**两轮 720 步、1336 万 token、0 产物**）。
> 加 `--install` 可自动装渲染依赖；`--json` 给程序读。
>
> **它只管环境，不碰任何创作**（页面/样式/时长/文案全部由你决定 ✓）。

### 2.1 `render\` 目录要先装依赖

`render.mjs` / `still.mjs` 的唯一依赖是 **`playwright-core ^1.45.0`**（`tools/render/package.json` 里写死的）。
技能包里**没有**带 `node_modules`（体积原因）。第一次用先：

```powershell
cd tools\render
npm install          # 只装 playwright-core，不下载浏览器（本机用系统 Edge）
```

**本机没有 Chrome**（`Program Files` 下也没有），**必须**设：
```powershell
$env:CHROME_PATH = 'C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe'
```
`render.mjs` 第 15 行原文逻辑：`process.env.CHROME_PATH ? { executablePath: … } : { channel: 'chrome' }`
⇒ **不设这个环境变量，它会去找 Chrome 然后直接失败。**

### 2.2 ffmpeg 必须进 PATH

`beatmap.mjs` 用 `spawn('ffmpeg')` 解码音频 —— **ffmpeg 不在 PATH 就 ENOENT**：

```powershell
$env:PATH = 'D:\MiniMax Design\current\resources\ffmpeg;' + $env:PATH
```

### 2.3 ★★ ffmpeg 还必须**带 libx264**（2026-12-13 实测新增，最阴的一条）

**PATH 上那个 ffmpeg 可能是残缺版**：本机实测
`D:\Software\GPT-SoVITS\...\runtime\ffmpeg.EXE` **没有 libx264**，
用它渲染会在**编码那步**才崩，报：

```
Unknown encoder 'libx264'
```

**怎么确认哪个是完整的**：

```powershell
ffmpeg -hide_banner -encoders | Select-String libx264
# 有输出 = 能用；没输出 = 残版，换成完整那个
```

`preflight.py` 会自动替你判断，并把**完整那个**的目录填进要复制的命令里 ✓

## 4. 三个脚本各自怎么用（**与 SKILL.md 对应步骤**）

### `beatmap.mjs` —— 第 3 步节拍检测（机器初稿）

```powershell
node tools\render\beatmap.mjs track.mp3 data\beats.json --trim track-trimmed.wav
```
- 参数：`--bpb 4`（每小节拍数）、`--tol 1.5`（常量速度段合并容差，百分比）
- 输出字段：`{ file, duration, offset, beatsPerBar, tempo:[{bar,bpm}], bars, maxDriftMs, beats, downbeats, quiet, hits }`
- **`maxDriftMs > 40` 时必须直接切 `beats` 数组**，不许用常量 BPM 映射（脚本自己会打印这句）
- 极短/无脉冲音乐会退出：`too few beats found: is music with a pulse?`
- ⚠️ **它的输出是初稿不是结论**——本机实测它把 120 BPM 点轨判成 **181.82 BPM**（八度错误）。**第 4 步复核是硬门。**

### `render.mjs` —— 第 7 步逐帧渲染

```powershell
node tools\render\render.mjs index.html renders\video.mp4 --workers 1 --from 0 --to 10   # 先小片段跑通
node tools\render\render.mjs index.html draft.mp4 --draft                                # 迭代期草稿
node tools\render\render.mjs index.html renders\video.mp4 --workers 4 --profile          # 放量
```
- **必须挂后台**（单条命令 60 s 上限；18 秒片 540 帧那次前台跑就超时了）——见 `时长档位表.md` §4
- 页面契约不满足时渲染器直接退出（`window.__meta` / `window.__draw` / `window.__ready`）

### `still.mjs` —— 第 8.2 步关键帧原尺寸

```powershell
node tools\render\still.mjs index.html stills\ 12.5 34 61.2
```

### 4.1 `make_click_track.py` 怎么用（**它是个"对照诊断脚本"，别当工具直接跑**）

**它实际做的事**：把「SKILL.md 原来那条命令」和「逐拍 `adelay` 的正确做法」**各跑一遍并数 click 响数**，
用实测数字证明旧命令**只出 1 响**。所以它里面：

- 路径**写死**指向那次小样的目录（`ROOT\assets\audio\music\bgm.wav`、`ROOT\data\beats.json`）；
- 会额外产出一个 `music_with_clicks_literal.wav`（故意复现错误命令的产物）。

⇒ **换项目直接跑会找不到文件**。两种正确用法：

**(a) 当参考实现读**——它把两个坑写清楚了，照这两条改自己的命令：

| 坑 | 现象 | 正确写法 |
|---|---|---|
| `adelay` 的声道 | 只给一个数：`adelay=500` 在多声道下行为不一致 | `adelay=delays=<ms>:all=1`（`all=1` = 所有声道同延迟） |
| click 音量 | `lavfi` 的 `sine` 默认振幅只有 **0.125**（实测 `max_volume -18.1 dB`），再乘 0.6 → **≈ −22.5 dBFS**，**埋在音乐下面根本听不见** | 显式放大（那次用 `volume=3.0`），并且**音乐侧先 `-5 dB`**，否则 float 峰值 1.54 写 s16 会削波 |

**(b) 换成自己项目的最小可跑版**（推荐，直接抄这段）：

```python
# make_click_track.py —— 按 data/beats.json 逐拍摆 click，输出 music_with_clicks.wav
import json, subprocess
FF = r"D:\MiniMax Design\current\resources\ffmpeg\ffmpeg.exe"
beats = [b["t"] if isinstance(b, dict) else b for b in
         json.load(open("data/beats.json", encoding="utf-8"))["beats"]]
N, CLICK_VOL, MUSIC_DB = len(beats), 3.0, -5.0
parts = [f"[1:a]asplit={N}" + "".join(f"[c{i}]" for i in range(N))]
for i, b in enumerate(beats):
    parts.append(f"[c{i}]adelay=delays={round(b*1000)}:all=1,volume={CLICK_VOL}[k{i}]")
graph = (f"[0:a]volume={MUSIC_DB}dB,aformat=channel_layouts=stereo[mus];" + ";".join(parts) + ";"
         f"[mus]" + "".join(f"[k{i}]" for i in range(N)) + f"amix=inputs={N+1}:normalize=0[out]")
open("click-graph.txt", "w", encoding="utf-8").write(graph)   # 长图必须走文件，别塞命令行
subprocess.run([FF, "-y", "-i", "music.wav", "-f", "lavfi", "-i", "sine=frequency=1500:duration=0.03",
                "-filter_complex_script", "click-graph.txt", "-map", "[out]",
                "-c:a", "pcm_f32le", "music_with_clicks.wav"], check=True)
```

**验收这条复核做没做成的判据**：**响数 == 拍数**（那次是 **20/20**，偏差 **+0 ms**）。
**只要响数 ≠ 拍数，这条复核就没做成**，别拿它签"复核 B 通过"。

## 5. 这一页的诚实边界

- **脚本内容是原样复制的**，本次会话**没有**逐个读完 7 个脚本的全文，也没有在技能包里跑一遍它们。
  已核对的只有：**存在、字节数、行数、`package.json` 的依赖声明、`render.mjs` 读 `CHROME_PATH` 的那一行、
  `beatmap.mjs`/`fit-beat-grid.py` 的头部注释**。
- **`npm install` 没有在技能包目录里跑过**（本机 `tools\render\node_modules\playwright-core` 是 10 秒小样那份的，没复用到包里）。
- `tools\` 目录**不在 SKILL.md 的 `load_skill` 送达范围内**（应用只送 SKILL.md 正文 + `references\`）——
  ⇒ **agent 必须自己 `cp` 或按第 3 节把 `tools\` 拷出来**，不能假设它已经在工作目录里。
- 这些脚本是**参考实现**，不是"唯一正确写法"：本机 18 秒那条片子就是 agent **自己等价改写**的
  （`build_timeline.py` / `render.py`），一样跑通了。**照抄可以，改写也允许，但都得自己复核。**
