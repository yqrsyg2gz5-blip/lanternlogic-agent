## 9. ★ 配音与画面时长对齐（SKILL.md 硬要求）

**做法 A · 行级（不依赖额外工具）**：用 `ebur128` 或简单 RMS 找出**人声实际起点**，与该行在 `TIMING` 里的 `on` 比较。

```powershell
# 抽成片音轨，再看第 t 秒附近能量跳变（配合 python 读 f32le 更精确）
& $FF -v error -y -i $V -vn -acodec pcm_s16le out\qa\render.wav
& $FF -hide_banner -nostats -i out\qa\render.wav -af "silencedetect=n=-45dB:d=0.15" -f null NUL 2>&1 |
  Select-String 'silence_end'   # 每个 silence_end 就是一句人声的起点候选
```

**做法 B · 词级**：用第 10 节的干声掩码法，逐词比对 `TIMING.captions[].words[].s` 与音轨。

**验收标准**
- **⚠️ 先补偿，再套线**：`edge-tts` 的 `WordBoundary` 时间戳与 mp3 解码后可听起点之间有 **70–95 ms 系统性滞后**（本机 2026-10-12 复测：70 / 80 / 90 ms；制作方自己量到 75 / 80 / 95 ms）。**裸测永远不达标**，与片子做得好坏无关。
  ⇒ 第 2 步每行量出 `acOffset`（首词 `s` − 可听起点），第 5 步排布时整体前移，**8.7 验的是补偿后的残差**。
- 人声实际起点（**补偿后**）与该行 `on` 的**偏差 < 50 ms**；
- 每条字幕出入点误差 **≤ 2f**；
- **连续两条字幕不重叠**；
- **不留哑巴段落**（纯动画段落也要有解说 caption，见第 18 节 8.13）；
- **报告两个数**：`补偿前滞后 = __ ms` + `补偿后残差 = __ ms`。只报后者 = 隐瞒已知偏差 ✗。
- ⚠️ **未验证**：`acOffset` 是否跨音色/语速恒定——只测过 `zh-CN-XiaoxiaoNeural` 的 3 行，**换音色必须重新量，不许照抄 0.08 s**。

**复测 `acOffset` 的命令**（本会话跑过的原样写法）：

```python
# measure_vo_offset.py —— 10 ms 窗 RMS，取第一个超过「本行峰值 −35 dB」的窗起点 = 可听起点
import json, subprocess, numpy as np
FF = r"D:\MiniMax Design\current\resources\ffmpeg\ffmpeg.exe"
def decode(p, sr=24000):
    raw = subprocess.run([FF, "-v", "error", "-i", p, "-ac", "1", "-ar", str(sr), "-f", "f32le", "-"],
                         capture_output=True, check=True).stdout
    return np.frombuffer(raw, dtype=np.float32), sr
def onset(x, sr, win_ms=10, rel_db=-35.0):
    n = max(1, int(sr * win_ms / 1000)); m = len(x) // n * n
    db = 20 * np.log10(np.sqrt(np.mean(x[:m].reshape(-1, n).astype(np.float64) ** 2, axis=1) + 1e-12) + 1e-12)
    return int(np.argmax(db > (db.max() + rel_db))) * win_ms / 1000.0
lines = json.load(open("data/vo-lines.json", encoding="utf-8"))
for l in lines["lines"]:
    x, sr = decode(l["file"]); print(l["id"], (onset(x, sr) - l["words"][0]["s"]) * 1000, "ms")
```

## 13. 卡点命中率回测（**未验证：本机没有 librosa**）

先抽音轨：

```powershell
& $FF -v error -y -i $V -vn -acodec pcm_s16le out\qa\render.wav
```

再跑下面的脚本（改编自 video-shotcraft `music-beat-sync.md` 的方法，**原文用 librosa**）：

```python
# beat_verify.py —— ⚠️ 需要 librosa；本机系统 Python 与 agent-shell venv 都未在本轮验证过该链路
import numpy as np, librosa, json
y, sr = librosa.load("out/qa/render.wav", sr=None, mono=True)
tempo, beats = librosa.beat.beat_track(y=y, sr=sr, tightness=400, units="time")
i = np.arange(len(beats)); A = np.vstack([i, np.ones_like(i)]).T
T, t0 = np.linalg.lstsq(A, beats, rcond=None)[0]
bpm = 60.0 / T
res = beats - (t0 + i * T)                     # 网格残差
print(f"BPM={bpm:.2f}  t0={t0:.4f}s  T={T:.5f}s  残差max={np.abs(res).max()*1000:.0f}ms")
plan = json.load(open("cut_points.json"))      # 设计切点(秒)：由 beatF(n) 换算而来
hit = [min(abs(np.array(beats) - p)) for p in plan]
print("切点距最近拍:", [f"{h*1000:.0f}ms" for h in hit])
```

**合格线（来自 video-shotcraft，**读到**；本机**未复现**）**

| 指标 | 合格线 |
|---|---|
| 网格可信度 | beat 序列最小二乘拟合**残差 ≤ ±15 ms（半帧）** |
| 节拍命中率 | **100% 切点落在拍上**；每个切点距最近拍误差 **≤ 3f（100 ms）**（参考片实测全部 ≤ **2.2f**） |
| 半速/双倍校验 | kick 落在**整数拍**的比例 **≥90%**，否则说明网格快/慢一倍，重算 |
| 大 slam 配额 | 整画面级冲击 **≤ 3 处**，相邻 **≥ 16 拍** |
| 音画偏移 | 补两项偏移后，探针残差 **≤ 0.5f**（实测 click 滞后 2032 samples、impact 2066 samples ≈ 1.27–1.29f @30fps；旧管线出现过 **4f≈133ms**） |

**交付前派一个干净上下文的 subagent 做第三方审查**：

- 最后分两轮梯度列出：**必须修复项 / 建议优化项 / 无法验证项**；
- 原文明说：**「制作 agent 自己出审查报告：确认偏差不可避免，独立 subagent 审查不可省略」「首检永远不能交给用户」**。

**画面技术质量清单（部分可脚本化，部分靠抽帧肉眼）**

| 指标 | 合格线 |
|---|---|
| 构图与文字 | 文字不与物体重叠、不压最亮处；不出安全区；每条字幕停留够久可读；每帧都明确「该看哪」 |
| 运动与节奏 | **无超过 2 s 的完全静止段**（设计内 hold 除外）；该缓动的没用线性；镜头朝高潮变短、高潮前有停顿；前 2 秒抓住观众（竖屏） |
| 视觉 | 物体不该出界的没出界；帧间无突然亮度跳变（除刻意闪白）；配色一致；强调色没糊满整屏；**无 `Math.random()` 造成的闪烁** |
| 声音 | 切点落在拍上；静默后无孤立重击；**人声在音乐之上清晰可懂**；最终响度约 −14 LUFS |
| 技术 | 字体在第一帧前已加载；**两次渲染结果完全一致**；画面标签不压 HUD 角标；实时预览与渲染时间一致 |
| 其它 | 无意外裁切、无元素重叠、边距一致、宽高比正确、**无占位素材**；飞入/升起动画终点必须落进真实槽位**不许悬空**；光效必须被 `border-radius/overflow` 裁住；**同一镜头只能有一个震源**；转场必须落在拍上 |

**验证法（很值得抄）**：「Watch once with audio only, once muted, then together. **The visuals must still have intentional rhythm when the audio is removed.**」——先只听、再静音看、最后合看。

### 18.1 尾部空转（8.11）

**怎么测**：逐帧平均亮度差按秒分桶（第三方审查用的是这个口径，可直接抄）：

```python
# 逐帧平均亮度 -> 相邻帧差 -> 按秒分桶求 mean / max / 每 30 帧里 >1.0 的帧数
# 第三方审查实测输出（10 秒小样，反例）：
#   7.0-8.0s  mean=11.302 max=162.383   <- 7.533s 白闪转场
#   8.0-9.0s  mean= 0.432 max=  3.997   30 帧中仅 3 帧 >1.0
#   9.0-10.0s mean= 0.438 max=  2.734   30 帧中仅 2 帧 >1.0
#   对照 0-7.5s：每段 mean 0.84-1.21，每 30 帧有 10-15 帧 >1.0
```

**合格线**：**不许出现「连续 ≥2 个拍点无任何变化」的尾巴。**
反例判定：7.533 s 之后再无切点，**7.5 / 8.0 / 8.5 / 9.0 / 9.5 五个拍点全部空转 = 全片 25%** ✗
**返工去向**：回第 5 步把这些拍点用起来（字标动效 / 收尾 SFX / 幕落），**或直接把 `DURATION` 缩短**——留着空转不算"设计内 hold"。

### 18.2 逐字高亮必须跟词时间戳（8.12）

**怎么测（三步，都要做）**：
1. **量前沿速度均匀性**：crop 到字幕行，逐帧统计高亮色像素的前沿位置 → 求速度曲线。
   反例实测：**110–120 px/s（0.7–2.7 s）→ 峰值 355 px/s（3.13–3.33 s）→ 回落 110 px/s（4.5–4.97 s）**，
   整体线性拟合 **R²=0.969**（= 一条直线 ⇒ 匀速动画）。**快慢差 4 倍** ✗
2. **把每个字格"变亮时刻"列出来，和人声停顿区间比**：
   反例实测：字格变亮间隔 **0.400 / 0.367 / … / 0.100 / … / 0.400 s**（首尾一个字亮 0.4 s、中段仅 0.1 s），
   且第 4 字格 **1.933 s** 变亮时人声 **1.86–2.16 s 是停顿**；第 18 字格 **4.800 s** 变亮时人声 **4.560 s 已结束**
   ⇒ **人声停顿里高亮照常前进 = 定时动画，不是逐词跟读** ✗
3. ★ **量「词尾过冲」**（2026-10-12 新增，最容易漏）：
   驱动源对了**也可能**对不齐 —— 动画窗口用了 `[ws, we]`，而 `we` 比真正发声尾巴长 ⇒ **字幕慢半拍**。

   ```python
   # ★ 必须在「人声干声」上量，别用混音轨（音乐铺底会让静音检测失效 —— 本轮踩过）
   #   干声常见位置：assets/audio/stems/stem-voice.wav 或 out/audio/voice_stem.wav
   import json, subprocess, numpy as np
   FF = r"D:\MiniMax Design\current\resources\ffmpeg\ffmpeg.exe"
   VOICE, SR = "assets/audio/stems/stem-voice.wav", 24000
   x = np.frombuffer(subprocess.run([FF,"-v","error","-i",VOICE,"-ac","1","-ar",str(SR),
                                     "-f","f32le","-"],capture_output=True,check=True).stdout, dtype=np.float32)
   W = int(SR*0.005); m = len(x)//W*W
   db = 20*np.log10(np.sqrt(np.mean(x[:m].reshape(-1,W).astype(np.float64)**2,axis=1)+1e-12)+1e-12)
   voiced = db > (db.max() - 35.0)          # ★ 阈值必须写明：统一用「峰值 −35 dB」
   tl = json.load(open("data/timeline.json", encoding="utf-8"))
   bad = 0; tot = 0
   for c in tl.get("captions") or []:
       for w in (c.get("words") or []):
           if not (isinstance(w,(list,tuple)) and len(w)>=3): continue
           ws_,we_ = float(w[1]), float(w[2])
           if we_-ws_ < 0.12: continue
           lo = max(0,int((we_-0.8)/0.005)); hi = min(len(voiced), int(we_/0.005)+1)
           idx = np.nonzero(voiced[lo:hi])[0]
           if not len(idx): continue
           real = (lo+idx[-1])*0.005
           over = we_-real; tot += 1
           if over > 0.040: bad += 1
           # print(f"{w[0]:>8} 窗口 {ws_:.2f}-{we_:.2f} 实际发声到 {real:.2f} 过冲 {over*1000:.0f}ms")
   print(f"过冲>40ms 的词 = {bad}/{tot}")
   ```

**合格线**：每个字 span 的**亮起时刻 = 该词在 `TIMING` 里的 `s`**（由词时间戳驱动）；
**人声停顿期间高亮不得前进**；**词尾过冲 ≤ 40 ms**（超过 40 ms 的词占比不得 >10%）。
**同一句内不同字可以不同状态**（这是必要条件，**不是充分条件**）。
**返工去向**：回第 6 步 ① 把驱动源从"定时器/缓入缓出擦除"改成"绑 `words[].s`"；
② 把动画窗口尾从 `we` 收紧到**实际发声尾**（`min(we, 最后一个有声窗的时刻)`）。

⚠️ **两个口径必须一并写进报告**，否则两次测量不可比：
- **相对阈值**（本技能统一 **−35 dB**；本轮先用 −30 dB 量得"中位 4 ms"差点放过，换 −35 dB 才看清尾部）
- **看分布而不是中位数**：那 30 秒片过冲**中位只有 4 ms**，但**均值 29 ms、41% 的词 >40 ms、16% >80 ms、最大 109 ms** —— 只报中位数等于把问题藏起来 ✗

### 18.3 字幕覆盖率（8.13）

**怎么测**：逐帧统计字幕（含高亮色）出现的时长 ÷ 全片时长。
反例实测：青色像素只在 **f16–f149（0.533–4.967 s）** 出现，0–0.533 s 与 4.967–10.0 s **青色像素总数 = 0**
⇒ 5.0 s 后的三张卡片与 7.5 s 后的片尾标题**全程无字幕**，**覆盖率 44%** ✗

**合格线**：**≥ 80%**；**纯动画段与片尾字标段也必须挂 caption**。
（"人声结束了所以不用字幕"不成立——观众看的是信息密度，不是有没有人说话。）
**返工去向**：回第 5 步补 caption 条目。
