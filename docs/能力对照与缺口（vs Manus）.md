# 能力对照与缺口 · LanternLogic Agent vs Manus 形态（2026-09-30）

> **作者的问题**："按 Manus 2.0 那个模式，它达到功能了吗？还差哪一步？还有什么没做？"
> **方法**：把**当前代码里真实存在的东西**逐项对照（工具清单是从 `app.main.TOOLS` 读出来的，
> 技能是扫目录得到的，不是凭印象）。
> **结论先给**：**核心能力覆盖约 75–80%**，差的不是"有没有"，而是**三个体验级缺口**；
> 按"录视频宣传"这个目标排序，最该补的是**成果展示界面**。

## 三、还差哪一步：三个缺口，按你的目标排序

### 🥇 缺口 1 · 成果展示界面（Studio）—— **录视频最缺的就是这个**
**现状**：前端只有 4 个组件。做完一个网站 / 幻灯片 / 数据报告，
用户只能看到**侧栏文件列表**，点一下用 raw 打开。
**问题**：**没有"哇"的瞬间**。Manus 的视频里最有冲击力的画面，
就是右边那块**直接渲染出网页/表格/幻灯片的成果面板**。
**建议**：做一个"成果"标签页 ——
- 识别产物类型（`.html` 内嵌 iframe 预览、`.csv/.xlsx` 渲染成表格、`.md` 渲染、图片画廊）
- 幻灯片类给缩略图列表
- 一键"在浏览器打开 / 下载 / 复制路径"
**工作量**：约 1–2 个班次（纯前端 + 少量接口），**对录视频的收益最高**。

### 🥈 缺口 2 · 沙箱（设计已就绪，未实现）
**现状**：`shell_exec` 以你的全权限运行，靠"审批 + 只读免审批 + 可回滚"兜着。
**对自用**：够。**对演示**：是卖点（"它敢乱来，因为伤不到你"）。
**建议**：按 `docs/design/沙箱执行器（可选Docker）.md` 做**可插拔执行器**——
但你的机器 Docker 是坏的，**建议先不碰**；真要演示时用"只读免审批 + 交付对账"这个故事讲。

### 🥉 缺口 3 · 技能库规模（6 个 → 更多）
**现状**：6 个技能都是通用型。
**建议**：技能是**成本最低、效果最直观**的扩展点（一个 `SKILL.md` 就是一个新玩法）。
录视频时"技能清单"本身就是亮点。

### 其余缺口（知道就好，不急）
- **工具并行**：架构议题（外部报告 `09`），等真实使用暴露"慢"是主要痛点再说
- **多模态输入**：确认"拖图片进任务"能不能用；不能的话补一条输入链
- **长任务自治**：`max_iterations: 25` 对复杂任务是上限，可按需调

## 四、一句话回答你的问题

> **"达到它的功能了吗？"** —— **核心能力到了七五成**：工具、浏览器自动化、并行研究、
> 记忆、审批、交付可信度**都不缺**，有些地方（交付可信度、人在环里）还更好。
>
> **"还差哪一步？"** —— **差在最"看得见"的那一步**：
> **它干完活之后，成果没有一块像样的展示区。**
> 对自用无所谓，**对录视频宣传是致命的** —— 观众看不到"它做成了什么"。

**所以下一步我建议：做「成果展示界面」。**（而不是继续清技术债——技术债已经清完了）
