# 发版前必做（Release Checklist）

> ★★ 这份清单是**用血换来的** —— 2026-10-14 一次发版验收当场抓到**两个"发出去用户也用不了"的 bug**。
> 用户原话：
> 「你能不能就是好好细心点，你一次性我不管你说是浪费多少token，一次性给他做好审查测试，
>   你都弄好了，你再上传是不是？你别他妈老弄个半瞎子，然后就上传，不好，
>   然后别人下载完了，口碑也不好。」

**规矩：下面每一步都要「真跑」，不许看代码猜。全绿才允许 `git push`。**

---

## 0. 先问自己三句话（拿不准就别往下走）

1. **这件事我拿不准吗？** ⇒ 先上网查 / 先查官网文档，**不许靠猜** ✗
2. **这个行为我没验过吗？** ⇒ **先测一测**，别凭判断改代码 ✗
3. **这次改动会不会把别的弄坏？** ⇒ 想清楚影响面，必要时**先测基线**再动 ✓

---

## 1. 代码门（仓内）

```powershell
cd <仓库根>
.\scripts\check_all.ps1
```

必须 **5 项全绿**：

| 项 | 要求 |
|---|---|
| pytest（全量） | 全通过（跳过项要能说出为什么） |
| pyflakes | exit 0 |
| tsc --noEmit | exit 0 |
| 前端产物新鲜度 | `dist` 比源码新；界面关键字在产物里 |
| redgreen（193 组） | 全 PASS（**要求工作区干净** ⇒ 先提交再跑） |

> ★ redgreen 要求干净树：**提交一次 → 再跑一次门**，别只看第一次的结果。

---

## 2. 界面验证（真浏览器，不许只看代码）

用 playwright 真点一遍**这轮改的界面**：

- 打开应用（本地 127.0.0.1:8642）
- 点到改动的那块（例：模型弹层里的「思考 关·低·中·高」）
- **点一下，然后打接口确认真的存进去了**（不是只看界面变了）
- **控制台报错必须 0 条**
- 截图存证

> ★ 本班教训：界面"看着对"不等于能用 —— 必须**点一次 + 查接口**才算验过。

---

## 3. 真机跑一条任务（最关键的一步）

**在便携版上**派一条**真任务**（不是单元测试），跑到**自然结束**：

- ❌ **不许中途重启应用** —— 重启会把它掐死（本班就这么毁过一次验证 ✗）
- 盯这几个信号：

| 信号 | 健康值 | 危险值 |
|---|---|---|
| **写文件次数** | 15~47 | **0**（= 光研究不动手） |
| 起渲染器次数 | ≥1 | 0 |
| 试字体次数 | ≤10 且不增长 | 一路上涨（老毛病复发） |
| 状态 | done | partial/failed（要能解释为什么） |

> ★ 「写文件次数」是**提前看出成败的唯一硬信号** —— 出过片的任务都写了 15~47 次。

---

## 4. 发版体检（仓内脚本）

```powershell
python scripts\release_check.py
```

它**真跑**这些（全绿才行）：

1. 渲染器依赖齐不齐（按 `package.json` 声明逐项查）
2. 浏览器找得到吗（`CHROME_PATH` → Edge → Chrome）
3. ★ **真渲 3 秒** —— 唯一能证明"开箱能出视频"的办法
4. 导出清单会不会带上被 `.gitignore` 排除的运行时依赖
5. 前端产物在不在（用户别白屏）
6. 技能 / `start.bat` / `preflight`

---

## 5. 打包 + **解压后**验收（两次：轻量版 + full 版）

```powershell
# 打两个包（缓存残留会拒绝覆盖 ⇒ 先删 _build-cache）
python scripts\build_release.py --tag vX.Y.Z --out <空目录>
```

**然后对每个 zip 做**：

1. **全新解压到空目录**（模拟用户下载）
2. 干净性：不许有 `.git/` / `data/` / `*.bak-*` / 密钥
3. 今天的修复**一个不少**（逐项 grep 关键标记）
4. 前端产物在 + `index.html` 指向的 js 里含新界面关键字
5. `preflight.py` 能跑、技能清单对
6. **跑 `install.bat`**（full 版应报"包里都带好了，不用装"）
7. **起服务**（★ 用**临时端口**，绝不碰用户正在跑的 8642）
8. 起来后：接口通、界面不白屏、新功能字段在
9. ★★ **在解压后的包里真渲一次起手模板**，并且**故意不设 `CHROME_PATH`**
   （验它能不能自己找到 Edge —— 新用户机器上多半只有 Edge）

> ★ 本班就是第 9 步抓到了 `node_modules` 没打进包（`ERR_MODULE_NOT_FOUND`）✗

---

## 6. 上传（推两个平台）

```powershell
# 1) 导出干净副本（会自动强制带上被 .gitignore 排除的运行时依赖）
python scripts\export_public.py --out <空目录>

# 2) 同步进公开仓（保留 .git 历史）
#    把导出内容覆盖到公开仓工作区 → 提交 → 推
git -C <公开仓> add -A
git -C <公开仓> commit -F <消息文件>
git -C <公开仓> push origin main     # GitHub
git -C <公开仓> push gitee  main     # Gitee
```

提交消息里要写清：**现象 → 根因 → 改法 → 验证**（中文）。

---

## 7. 推完再验一次（别人下载的是不是好的）

1. 从**平台**重新下载 zip（不是用本地文件）
2. 走一遍第 5 步的 6~9（解压 → install → 起服务 → 渲染）
3. 都通过 ⇒ 才算真发完 ✓

## 附：本班踩过的坑（别重复）

| 坑 | 症状 | 防法 |
|---|---|---|
| `.gitignore` 排除了运行时依赖 | 用户渲染报 `ERR_MODULE_NOT_FOUND` | `export_public.py` 的 `FORCE_INCLUDE_DIRS` + 第 5.9 步 |
| 写死找 Chrome | 没装 Chrome 的 Windows 用户必失败 | 按 Edge→Chrome 顺序找 + 人话报错 |
| 缓存里旧树挡住重打 | `目标目录非空，拒绝覆盖` | 删 `_build-cache` 再打 |
| 中途重启应用 | 把正在跑的验证任务掐成 `failed` | 第 3 步跑完之前**不许重启** |
| 拿"界面看着对"当验证 | 看着对、其实存不进去 | 第 2 步：**点一次 + 查接口** |
| 中文引号嵌套 | `SyntaxError`（本班踩了 8+ 次） | 写脚本文件，中文里用 `「」` |
