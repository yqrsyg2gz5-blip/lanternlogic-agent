## 其他语言怎么办

规则只有一条 ✓：**用该语言的注释语法 ✓ 内容一字不改** ✓
（`.css` 用 `/* … */` ✓ `.html`/`.md` 用 `<!-- … -->` ✓ `.bat`/`.ps1` 用 `#` 或 `REM` ✓
 `.json` **不能有注释** ✗ ⇒ 放进 `package.json` 的 `"license"` 字段 ✓ 与 `NOTICE` 文件 ✓）

## 版本控制小贴士

- **新文件**：建的时候就带上 ✓（成本为零 ✓）
- **老文件**：不必为了加头而全仓翻一遍 ✗ —— 下次改到它时顺手加即可 ✓
  （法律上"仓库根有 LICENSE + README 有声明"已经足够 ✓ 文件头是**加强**不是必需 ✓）
- **自动检查**：可以在 CI 里加一条"新增的 `.py/.ts/.tsx` 必须含 `SPDX-License-Identifier: AGPL-3.0-only`" ✓
  想要的话告诉我 ✓ 我给你写这条检查 ✓

## 可选：用 SPDX 短标识代替长声明

不想每个文件贴十几行 ✓ 可以用 **SPDX 两行式**（一样有效 ✓ 且工具链友好 ✓）：

```python
# SPDX-FileCopyrightText: 2026 丹东振兴云杉互联网服务工作室
# SPDX-License-Identifier: AGPL-3.0-only
```

```typescript
// SPDX-FileCopyrightText: 2026 丹东振兴云杉互联网服务工作室
// SPDX-License-Identifier: AGPL-3.0-only
```

★ 两种都行 ✓ **别混用** ✗（要么全用长声明 ✓ 要么全用 SPDX 短式 ✓）
★ 但无论用哪种 ✓ **AGPL 第 13 条的源码获取方式**都要在**用户能看到的地方**给出 ✓
（README + 程序界面"关于"页 ✓ —— 光放文件头里**不够** ✓ 因为用户看不到源码文件 ✓）
