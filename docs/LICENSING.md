## 一、作者的原始设想（口述整理）

1. **前期**：自己使用 → 录视频 → 网上宣传（展示 Agent 能力到底好不好）
2. **验证后**：如果好、有人要买 → 就卖
3. **迭代策略**：在做出更好的功能迭代之前，**不开源**；
   等有了更好的版本，再把**最初的版本**开源 / 免费
4. **免费范围**：**只针对个人，不针对企业商用**
5. **商业模式**：
   - **个人版**：一次性费用，个人使用，**不可商用**
   - **商用版**：单独的商用费用，或提供部署服务，或商用版含额外功能

## 二、⚠️ 这条路上最大的一个坑（必须先知道）

> **一旦某个版本以 MIT / Apache-2.0 开源，那个版本就永久允许商用，收不回来。**
> MIT 明文允许"拿去卖钱、闭源再分发"。**若目标是"防商用"，选 MIT/Apache 等于自己把门拆了。**

所以"以后再开源"这句话，**必须区分开源的协议**：

| 协议 | 别人能商用吗 | 适合你吗 |
|---|---|---|
| **MIT / Apache-2.0** | ✅ 能，且不可撤回 | ❌ 与"防商用"矛盾 |
| **AGPL-3.0** | ✅ 能，但**改过的版本也必须开源**（很多企业直接禁用） | 🟡 可用，但对"个人免费"没帮助 |
| **BSL 1.1**（Business Source License） | ❌ 到期前只有你/获授权者能商用；**到期后自动转 Apache/GPL** | ✅✅ **几乎为你量身定做** |
| **PolyForm Noncommercial 1.0** | ❌ 明确禁止任何商业用途 | ✅ 适合"个人免费用、商用要钱" |
| **自定义 EULA**（闭源） | ❌ 完全按你写的来 | ✅ 适合当前阶段 |

### ⚠️ 用词提醒：这类协议**不叫"开源"**，叫「源码可见 / source-available」

**OSI 对"开源"的定义要求必须允许商业使用。** 所以"源码公开但只许个人用"的协议
**严格说不算开源**。这不是抠字眼：
HashiCorp 把 Terraform 改成 BSL 时被社区批评"假开源"，就是因为**宣称开源却禁商用**。

> **对外宣传建议**：说「**我把旧版本开放出来了，个人免费用**」，
> **别说「我开源了」** —— 否则容易被指责"假开源"，反而伤口碑。

## 二·补 · 你要的「源码可见 + 仅个人可用」有哪些成熟协议

| 协议 | 个人用 | 企业用 | 商用 | 到期自动开放 | 典型使用者 |
|---|---|---|---|---|---|
| **PolyForm Noncommercial 1.0** | ✅ 免费 | ❌ | ❌ 明确禁止 | ❌ | 大量独立软件 |
| **BSL 1.1**（Business Source License） | ✅ | ❌ 需授权 | ❌ 到期前不许 | ✅ **约定期限后自动转 Apache/GPL** | MariaDB、HashiCorp |
| **Elastic License 2.0（ELv2）** | ✅ | ✅ 内部可用 | ⚠️ 仅禁"拿它做托管服务卖" | ❌ | Elasticsearch |
| **CC BY-NC-SA 4.0** | ✅ | ❌ | ❌ | ❌ | 偏文档/内容类 |
| 自定义 EULA（闭源） | 按你写 | 按你写 | 按你写 | ❌ | **当前阶段** |
| ~~MIT / Apache-2.0~~ | ✅ | ✅ | ✅ **永久，收不回** | — | ❌ **与"防商用"冲突** |

### 你的模式在业界叫「双许可（dual licensing）」

```
同一份代码
├── 个人用户 → PolyForm Noncommercial（免费）   ← 或你的一次性付费授权
└── 企业用户 → 商业授权（付费 / 代部署 / 商用版功能）
```

MySQL、Qt、MongoDB 早期都用过这个模式：**个人随便用攒口碑，企业想用就得谈**。

### "最初版本以后开放"这一步，二选一

| 选择 | 效果 | 建议 |
|---|---|---|
| **BSL 1.1** | 约定 3–4 年后**自动**转 Apache-2.0；期间只有你能商用 | ✅ **既实现"延迟开放"，又防白嫖商用** —— 最贴合你的设想 |
| **一直用 PolyForm Noncommercial** | 永远只允许个人用，**不自动开放** | 若你不想让企业"等几年就能白拿" |

> **关键操作**：**同一份代码可以按版本用不同协议** —— 新版本闭源 / 旧版本 BSL 或 Noncommercial。
> 但必须在每个版本的 `LICENSE` 里**写清适用版本号**，否则会乱。

## 三、分阶段路线图（建议）

### 阶段 0 · 现在（闭源 + 保留所有权利）✅ 已完成
- 根目录 `LICENSE` = **All Rights Reserved** 占位条款（区分个人使用 / 商业使用 / 禁止行为）
- 仓库**不开源**；分发形态 = `install.bat` + `start.bat`（已验证可用）
- **待补**：`LICENSE` 里的联系方式；正式 EULA

### 阶段 1 · 自用 + 录视频宣传（进行中）
**宣传前必须先做的清理**（否则视频/截图里会暴露问题）：
- [ ] `HANDOVER.md` 里有「照抄泄露提示词」「可卖无侵权」等**自相矛盾**的表述 → 清理
- [ ] `AUDIT_REPORT.md`、`docs/collab/`、`讲解稿.md` 属于**内部材料**，
      若要公开仓库或截图，**先确认不含内部信息**（含内部评审结论、班次记录）
- [ ] README 里的「协议选择中」已过期 → 指向 `LICENSE`
**这个阶段不必开源**：闭源 + 保留所有权利即可。

### 阶段 2 · 开始售卖（个人版一次性 / 商用版另议）
- **协议**：仍是**闭源 + 正式 EULA**（不要开源）
- EULA 必须写清：个人版授权范围、**禁止商用**、不可转让、免责、退款政策
- **产品功能待补**（现在没有）：
  - **授权 / 激活机制**（一次性费用怎么发、怎么校验、怎么防串号）
  - **版本区分**（个人版 / 商用版的功能差异，或商用版的部署服务）
  - 试用期 / 退款流程
- **定价建议**：个人版一次买断；商用版按年或按席位；部署服务单独报价

### 阶段 3 · 做出更好的迭代后，"把最初的版本开源"
**这一步换协议时，按你的目的选**：
- **想防商用** → **BSL 1.1**：源码可见、商用受限、**约定 3–4 年后自动转 Apache-2.0**
  （正好实现"旧版本最终开放"的意图，且期间不被白嫖商用）
- **只想让个人免费用** → **PolyForm Noncommercial 1.0**
- **想彻底开放、放弃防商用** → 才考虑 Apache-2.0（不建议与"商用收费"并存）

> **关键提醒**：**同一份代码可以按版本用不同协议**（新版本闭源 / 旧版本 BSL）。
> 这是"延迟开源"的标准做法，但你必须在每个版本的 `LICENSE` 里写清适用版本号。

## 四、几个现实问题（提前想清楚）

| 问题 | 说明 |
|---|---|
| **"禁止商用"怎么执行？** | 靠 EULA + 商业客户的合规意识；个人用户很难查。**别指望技术手段完全堵住**，重点是让"愿意付钱的企业"有合规路径 |
| **代码里含第三方依赖，能否闭源？** | 需要看依赖的许可证。当前后端是 FastAPI/uvicorn/httpx/pydantic（**MIT/BSD 系，可闭源商用**）；前端 React/Vite（MIT）。**基本无阻碍**，但商用前应逐项核对 |
| **Tauri 若将来启用** | Tauri 2.x 是 MIT/Apache-2.0，**可免费商用** ✅ |
| **Docker 若将来做成沙箱** | **Docker Desktop 对大企业需付费订阅** —— 所以本项目**故意不把 Docker 做成硬依赖**（见 `docs/design/沙箱执行器（可选Docker）.md`） |
| **录视频前** | 先确认没有把 API Key、私人文件路径、真实任务数据录进去 |
