# 本地沙箱隔离方案（Windows 原生三层）· 2026-10-12

> **给非开发者看的一页**：这份方案回答四件事 —— **防什么 / 不防什么 / 怎么叠 / 怎么证明它真关住了**。
> 原则沿用本仓规矩：**只报验过的数字；没验过的写"未验证"**。

---

## 0. 一句话

> 让 Agent 跑命令时**降权 + 上缰绳 + 只给一个可写文件夹**，
> 从而**能看见本机的 ffmpeg / Python（干得了重活）**，但**碰不到系统和你其它的文件**。

**要买什么软件？不用。** 三个机制全是 Windows 自带的。
**走本地还是云？本地。** 走云会自毁"数据不出机"这个唯一护城河。

---

## 1. 现状：已有一个沙箱，但它把重活挡死了

`backend/app/executors/local.py`（第 577 行起）**已经实现了 Docker 沙箱**，且设计是对的：

```
命令进 --rm 一次性容器，只挂载任务工作区，--network none，--memory 512m
Docker 不可用时**明确报错**，绝不静默降级到真机执行   ← 这一条值得表扬
```

**但它有两个致命限制**：

| 限制 | 后果 |
|---|---|
| 容器里**没有 ffmpeg** | **做视频类任务必须把沙箱关掉**（技能里已写成铁律） |
| 容器里**没有项目的 Python 环境**（scipy / edge-tts / PIL…） | 配音、音频分析、波形图都干不了 |

⇒ 现实是：**开着沙箱只能干轻活；干重活就得关沙箱、在自己的真机上全权限跑。**
**这不是"有没有沙箱"的问题，是"沙箱选错了实现方式"。**

### 1.1 本机探测事实（2026-10-12 实测）

| 项 | 结果 | 影响 |
|---|---|---|
| OS | **Windows 11 家庭版** Build 26200 | ⚠️ 家庭版**没有** Windows Sandbox（专业版/企业版功能）⇒ 该路排除 |
| pywin32 | **已安装**（`win32job` / `win32security` 可用） | ✅ **不需要新增依赖** |
| 当前进程身份 | **非管理员**（普通用户 `DESKTOP-SFENEOM\y`） | ✅ 受限令牌**不需要管理员**（见 §3.1）；也意味着产品不该要求管理员权限 |
| Docker | 已装且服务在跑（29.8.0） | 保留为备选，不作为主路径 |
| ctypes | `kernel32` / `advapi32` / `userenv` 均可加载 | ✅ 不依赖 pywin32 也能做（纯 ctypes 可行） |

## 2. 威胁模型：**防谁**，先说清楚

**这一节最重要。** 本地沙箱与云沙箱的能力边界**根本不同**，混着说会自欺。

| | 大厂云沙箱 | 本项目（本地沙箱） |
|---|---|---|
| 防的对象 | **恶意的别的租户**（多租户，必须防越狱） | **Agent 自己闯祸**（使用者=机主本人） |
| 数据位置 | 送到云上执行 | **就在本机，一步不外传** ← 产品卖点 |

### 2.1 本方案**要防住**的（必须做到）

| # | 场景 | 举例 |
|---|---|---|
| T1 | **误删/误改用户文件** | Agent 写脚本时手滑覆盖 `C:\Users\y\Documents\...` |
| T2 | **越出授权目录** | 命令里出现 `../../..` 或绝对路径，写到工作区外面 |
| T3 | **跑飞 / 挂死** | 死循环、开一堆进程把机器拖死 |
| T4 | **留下后台残留** | 命令超时被杀，但它 fork 的子进程还在跑 |
| T5 | **改系统设置** | 改注册表、改 PATH、装服务 |

### 2.2 本方案**明确防不住**的（写出来，别对外宣称能防）

| # | 防不住的 | 为什么 | 那要什么才行 |
|---|---|---|---|
| N1 | **铁了心要越狱的恶意代码** | 同机本地沙箱永远弱于独立 VM：内核漏洞、`SeDebugPrivilege` 这类理论上能绕 | **独立虚拟机 / 物理隔离**（不是本阶段该花的钱） |
| N2 | **内核级攻击** | 同上 | 同上 |
| N3 | **它自己联网外传数据**（沙箱开着网的时候） | 本方案默认**断网**（§3.4），但用户开网时无法在网络层拦 | 网络出口白名单 / 独立网段 |
| N4 | **模型本身胡说** | 那是内容问题，不是执行隔离问题 | 交付前自检 + 独立审查（技能第 8 步） |

> ★ **沙箱 ≠ 审批门**，两者管的是不同问题：
> **审批门**管「**这条命令要不要跑**」；**沙箱**管「**跑起来之后它能碰什么**」。
> **两个都要**：只有审批 = 点一次"允许"就把整台机器交出去；只有沙箱 = 它会自己乱跑但碰不到系统。

## 3. 怎么叠：三层机制（全部 Windows 自带）

```
                 ┌─────────────────────────────────────────┐
   Agent 命令  → │  ① 受限令牌  →  降权，跑不出高权限操作    │
                 │  ② 作业对象  →  限资源 + 禁子进程 + 整窝杀 │
                 │  ③ 目录 ACL  →  只能写工作区，别处只读     │
                 └─────────────────────────────────────────┘
```

### 3.1 ① 受限令牌（Restricted Token）—— 降权

**做什么**：用 `CreateRestrictedToken` 从当前令牌派生一个**降权令牌**，子进程用它启动。

**关键参数**：

| 参数 | 作用 |
|---|---|
| `DISABLE_MAX_PRIVILEGE` | 把令牌里所有特权禁用（最省事、最常用） |
| `LUA_TOKEN` | 以"普通用户"身份跑（去掉管理员组） |
| `WRITE_RESTRICTED` | **写入受限**：只有"允许写入"的 SID 能写 —— 配合 §3.3 用 |

## 3.1bis ★ 实测修订：三层里**只有 ②③ 不需要管理员；① 需要**（2026-10-12 实测）

> **本节是方案落地时被实测推翻假设后补的**，读完再动手，别按 §3.1 的老假设去做 ✗

### 实测结论（本机 Windows 11 家庭版 · 普通用户身份）

| 尝试 | 用到的 API | 结果 |
|---|---|---|
| 建受限令牌 | `CreateRestrictedToken` | ✅ **成功**（不需要特权） |
| 用它起进程 | `CreateProcessWithTokenW` | ❌ **WinError 1314** —— 缺 `SeImpersonatePrivilege` |
| 同上（换一条） | `CreateProcessAsUserW` | ❌ **WinError 5** —— 缺 `SeAssignPrimaryTokenPrivilege` |
| 备用路：AppContainer | `PROC_THREAD_ATTRIBUTE_SECURITY_CAPABILITIES` | ⚠️ 能起进程（`cmd` 通），但 **`whoami.exe` / `ffmpeg` / `python` 全挂** `0xC0000142`（DLL 初始化失败）/ `0xC0000135`（DLL 找不到） |

**本机当前进程持有的特权**（实测）：

```
SeChangeNotifyPrivilege · SeIncreaseWorkingSetPrivilege · SeShutdownPrivilege
SeTimeZonePrivilege · SeUndockPrivilege          ← 全是普通用户默认那几个
SeImpersonatePrivilege        ✗ 没有
SeAssignPrimaryTokenPrivilege ✗ 没有
SeIncreaseQuotaPrivilege      ✗ 没有
```

### 两条硬结论

1. **受限令牌造得出、但用不了** —— 起进程要 `SeImpersonatePrivilege` 或 `SeAssignPrimaryTokenPrivilege`，
   这两个**普通用户默认没有**（要管理员）。
2. **AppContainer 对非打包的传统桌面程序不兼容** —— 连 `whoami.exe` 都起不来
   ⇒ `cmd` / `python` / `ffmpeg` 这类**全都跑不了**，
   而"能跑 ffmpeg / Python"**恰恰是本方案存在的唯一理由**（Docker 沙箱的毛病就是这个）。
   **这是机制边界，加 ACL 救不了** ✓

### 因此：本方案采用「**装时提一次管理员权限**」

| 层 | 是否需管理员 | 说明 |
|---|---|---|
| ① 受限令牌 | **需要**（起进程那一步） | 需要 `SeImpersonate` 或 `SeAssignPrimaryToken` |
| ② 作业对象 | 不需要 | 限制资源 / 整树杀 |
| ③ 目录 ACL | 设置时通常需要（写别人的 ACL） | 给受限 SID 配权限 |

**产品口径（要写进安装说明与文档）**：
> 本地沙箱隔离**需要一次管理员授权**（安装时）。这是**正经软件的做法** —— 杀毒软件、虚拟机、Docker Desktop
> 装的时候同样要管理员。**不给管理员权限时，本方案不启用，退回现有 Docker 沙箱或"关沙箱"** ✓
> **绝不**在没权限时假装开了沙箱 ✗（与现有 Docker 沙箱"不可用就明确报错、不静默降级"同一口径 ✓）

⚠️ **未验证**：拿到管理员权限后 ① 是否真能用（`CreateProcessWithTokenW` / `AsUser` 在提权下应可用 ——
**本机尚未在提权下实测**）⇒ P1 的第一步就是**在提权下重跑那三个探针**，过了才写实现 ✓

### 3.2 ② 作业对象（Job Object）—— 上缰绳

**做什么**：把子进程放进一个 Job Object，由它统一限资源、统一收尸。

| 限制 | 常量 | 值（建议） | 管什么 |
|---|---|---|---|
| 内存上限 | `JOB_OBJECT_LIMIT_PROCESS_MEMORY` | 2 GB | 防 T3 跑飞吃满内存 |
| 主动进程上限 | `JOB_OBJECT_LIMIT_ACTIVE_PROCESS` | 4 | 防它开一堆进程 |
| 不许再开子进程 | `JOB_OBJECT_LIMIT_ACTIVE_PROCESS = 1`（严格档） | 可选 | 防 T4 留残留 |
| **关掉即全杀** | `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` | **必开** | **主人一死，全家一起死** —— 这条专治 T4 |
| CPU 时间 | `JOB_OBJECT_LIMIT_JOB_TIME` | 按超时配置 | 防死循环烧 CPU |

**同时用 `AssignProcessToJobObject` + `TerminateJobObject`**：超时/取消时杀**整棵树**，而不是只杀直接子进程。

### 3.3 ③ 目录 ACL —— 只给一个可写文件夹

**做什么**：给受限 SID 配权限，让沙箱进程：

| 位置 | 权限 |
|---|---|
| **任务工作区**（`data/tasks/<id>/workspace`） | **读写**（干活要写产物） |
| 本机运行时目录（`runtime\` / `backend\.venv` / ffmpeg 目录） | **只读**（这就是"能看见本机工具"的关键） |
| 其它一切（系统盘、用户文档、桌面） | **禁止**（连列目录都不给） |

**实现要点**：
- 用 `SetNamedSecurityInfo` / `icacls` 给**受限 SID**（3.1 派生出来的那个）配 ACE
- **不要**给"Users"组配 —— 那等于对所有程序开口子
- 任务结束后**移除该任务的 ACE**（否则越攒越多）

### 3.4 网络

**默认断网**（与现有 Docker 沙箱口径一致：`--network none` 的等价物）。

- 实现方式（择一，实施时定）：**①** 受限令牌 + 防火墙出站规则按 SID 拦（需要管理员，**不适合普通用户安装**）；
  **②** 进程级不做网络拦截，**改为"默认不提供网络能力"**（即：沙箱只给本机工具，联网能力走**审批门**单独授权）
- ⚠️ **未验证**：普通用户权限下**能**做到"按进程断网"的手段有限，**实施前必须先小样验证**（见 §6 验收）

### 3.5 三条路怎么分工（**关键设计**）

| 活 | 走哪条路 | 理由 |
|---|---|---|
| **轻活**（读文件、跑脚本、查目录） | **本地原生沙箱**（本方案） | 快、能看见本机工具 |
| **重活**（做视频 / 渲染 / 用 ffmpeg / 用 scipy） | **本地原生沙箱**（本方案） | ★ 这就是本方案存在的理由 —— **不用再关沙箱** |
| 需要**强隔离**的（用户主动选） | 现有 **Docker 沙箱**（保留不动） | 用户愿意牺牲能力换隔离时的选项 |

**注意**：本方案是**多一条路**，**不删 Docker 那条**。现有行为和它的"绝不静默降级"原则一个字都不改。

## 6. 怎么证明它真关住了（**不许靠嘴说**）

每条都必须是**能跑的测试**，且**先红后绿**（仓规 ②）：

| # | 场景 | 测试怎么做 | 期望 |
|---|---|---|---|
| V1 | **T1 误改用户文件** | 沙箱里执行"往 `C:\Users\<u>\Documents\probe.txt` 写一行" | **失败**（Access Denied），且该文件**不存在** |
| V2 | **T2 越出工作区** | 沙箱里执行"写 `..\..\..\probe.txt`" | **失败** |
| V3 | **T3 跑飞** | 沙箱里跑死循环 + 申请大内存 | 在配置时间内被**强制终止**，进程消失 |
| V4 | **T4 后台残留** | 沙箱里启动一个后台进程后主进程退出 | **子进程也一起死**（`KILL_ON_JOB_CLOSE`） |
| V5 | **T5 改系统** | 沙箱里执行 `reg add HKCU\...` / 改 PATH | **失败** |
| V6 | **能干重活（本方案的核心目的）** | 沙箱里跑 `ffmpeg -version` + `python -c "import scipy"` | **成功**（证明"开着沙箱也能干活"） |
| V7 | **正常活不受影响** | 沙箱里读文件、写工作区产物、跑普通脚本 | **成功**（别把正常活也拦了） |

**V6 是本方案的"立身之本"**：如果它不过，本方案就没有存在意义（那还不如继续用 Docker）。

## 7. 风险与诚实边界

| 风险 | 说明 | 应对 |
|---|---|---|
| **受限令牌 + ACL 组合可能有坑** | 本机**未实测**；`WRITE_RESTRICTED` 在非管理员下的行为未知 | P1 先做最小可用版；P2 不通就停在 P1 并记录 |
| **跨盘/符号链接绕过** | 用户工作区若有 junction/symlink 指向别处，ACL 可能被绕 | V2 要**加一条 symlink 用例** |
| **杀进程树有竞态** | `TerminateJobObject` 与进程创建的竞态经典问题 | V4 要用"立即创建 + 立即退出"的压力用例 |
| **企业评审仍不认** | 本地沙箱弱于独立 VM，安全评审严格的企业仍会要 VM | 对外口径写"本地隔离"，**不写"企业级隔离"** |
| **性能开销** | 受限令牌创建 + ACL 设置每次命令都有开销 | 验收时量一次"加沙箱前后单条命令耗时差"，写进报告 |
